# Contributing

## Layout

| Path | What |
|---|---|
| `crates/legal-grammar` | The citation, pinpoint, reference and provision grammar corpus (`data/grammar-corpus.json`) with its test vectors |
| `crates/legal-citations` | The engine: find, classify, metadata, parallel, resolve, key, format, url, annotate, clean; `api.rs` is the JSON surface every binding uses |
| `crates/legal-citations/registry` | Courts, reporters, series, journals, jurisdictions as JSON (`upstream/` is generated) |
| `crates/legal-citations-cli` | The `legal-citations` binary; hosts the Rust conformance and schema tests |
| `crates/legal-citations-py` | PyO3/maturin package `legal_citations` (and the `legal_citations.eyecite` facade) |
| `crates/legal-citations-wasm` | wasm-bindgen build and the npm package in `js/` |
| `conformance/` | Language-neutral cases, the JSON Schema, the Python/JS runners and the eyecite port tool |
| `tools/` | `sync-upstream.py` (registry from reporters-db/courts-db), `eyecite-diff.py` (differential harness) |

## Rules

1. **Citation grammar lives in the corpus.** Every pattern that recognizes
   citation text goes in `crates/legal-grammar/data/grammar-corpus.json` with
   test vectors (`input`, expected `groups`); no ad-hoc regexes for citation
   shapes in engine code. `cargo test -p legal-grammar` runs every vector.
2. **Registry data is JSON.** Courts, reporters, series and journals are
   edited in `crates/legal-citations/registry/*.json`, never in Rust. Files
   under `registry/upstream/` are generated by `tools/sync-upstream.py`; do
   not edit them by hand.
3. **Every behavior change adds conformance cases.** Add or update cases in
   `conformance/cases/*.json` in the same change (see
   [conformance/README.md](conformance/README.md)). A new case that already
   passes is `pass`; one that documents a known gap is `pending`.
4. **The JSON surface is shared.** New API methods and request fields go in
   `crates/legal-citations/src/api.rs` first; the Python, npm and CLI layers
   only translate names. A change to the serialized `Citation` updates
   `conformance/schema/citation.schema.json` (the schema test fails
   otherwise); a breaking change bumps `api::SCHEMA_VERSION`.
5. **Key v2 is a contract.** Anything that changes an existing key needs a new
   `KEY_VERSION` (see `crates/legal-citations/src/key.rs`).

## Checks

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test -p legal-grammar -p legal-citations -p legal-citations-cli   # vectors, engine, conformance, schema
python tools/sync-upstream.py --check                                   # registry matches upstream.lock

# Python binding + conformance through it
pip install maturin pytest
(cd crates/legal-citations-py && maturin develop --release)
python -m pytest crates/legal-citations-py/tests && python conformance/run.py

# npm package (needs wasm32-unknown-unknown and wasm-bindgen-cli at the version pinned in
# crates/legal-citations-wasm/Cargo.toml; wasm-opt is used when installed)
crates/legal-citations-wasm/build.sh
node conformance/run.mjs && (cd crates/legal-citations-wasm/js && node smoke.mjs)
```

## Conformance workflow

* A `pass` case that fails is a regression: fix the engine or, if the
  expectation was wrong, fix the case and say why in its `note`.
* A `pending` case that starts passing fails the run until it is marked
  `pass`. Mark every newly passing case at once with
  `python conformance/run.py --cli target/debug/legal-citations --promote`
  (or without `--cli` through the installed Python binding).
* `CONFORMANCE_FILTER=substring CONFORMANCE_VERBOSE=1 cargo test -p legal-citations-cli --test conformance -- --nocapture`
  shows why pending cases fail; `run.py --verbose` does the same.
* The eyecite-derived files (`eyecite-*.json`) are generated. To diverge from
  eyecite on purpose, edit the case's `expect` and add a `divergence` string
  explaining why; regeneration keeps both.

## Staying current with upstream

The weekly `upstream` workflow does all of this and opens a pull request; to do
it by hand:

```sh
python tools/sync-upstream.py --update            # move reporters-db/courts-db pins, regenerate registry/upstream
git clone https://github.com/freelawproject/eyecite /tmp/eyecite
python -m venv /tmp/ec && /tmp/ec/bin/pip install -e /tmp/eyecite
(cd /tmp/eyecite && /tmp/ec/bin/python "$OLDPWD/conformance/tools/port-eyecite.py" --eyecite /tmp/eyecite)
cargo build -p legal-citations-cli
python conformance/run.py --cli target/debug/legal-citations --promote
/tmp/ec/bin/python tools/eyecite-diff.py --conformance --cli target/debug/legal-citations \
    --baseline tools/eyecite-diff-baseline.json --report eyecite-diff.json
```

`port-eyecite.py` runs eyecite's own tests with its entry points wrapped,
records every input and real eyecite's output, maps it onto this model and
records the eyecite commit in `conformance/tools/eyecite.lock.json`. Existing
case names keep their status when their input is unchanged; new ones arrive
`pending`. `eyecite-diff.py` pairs citations by span and reports `missed`,
`extra` and field `mismatch` per citation; with `--baseline` it fails when
missed or mismatch counts grow. Refresh the baseline with `--write-baseline`
once a change is reviewed.

When upstream data introduces a surface that collides with a Commonwealth
one (`OR`, `CLR`, `FCA`, `S.C.`), keep the authored entry first and add a
conformance case for both readings.

## Releases

Bump `version` in the root `Cargo.toml` (all crates share it), add a
`## [x.y.z]` section to `CHANGELOG.md`, and push a `vx.y.z` tag. The `release`
workflow checks the tag, then publishes `legal-grammar`, `legal-citations` and
`legal-citations-cli` to crates.io, abi3 wheels and an sdist to PyPI, the npm
package, and CLI binaries to the GitHub release. Publishing uses trusted
publishing (OIDC); the workflow header lists the one-time registry settings
and the token fallbacks. Run it with `workflow_dispatch` (dry run) first.
