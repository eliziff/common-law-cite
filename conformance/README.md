# Conformance cases

Language-neutral test cases every binding must satisfy identically. Runners:

| Runner | Command |
|---|---|
| Rust (`api::call_value`) | `cargo test -p legal-citations-cli --test conformance` |
| Python binding | `python conformance/run.py` |
| CLI (`batch`) | `python conformance/run.py --cli path/to/legal-citations` |
| npm package (WebAssembly) | `node conformance/run.mjs` |

## Files

`cases/*.json`:

```json
{
  "format": "legal-citations-conformance:v1",
  "source": "where the cases come from",
  "description": "...",
  "cases": [
    {
      "name": "neutral/scc-with-paragraph",
      "input": "R v Jordan, 2016 SCC 27 at para 105.",
      "options": {"resolve": true, "offsetUnit": "char"},
      "status": "pass",
      "expect": {"citations": [{"form": "full", "fields": {"year": "2016"}}]},
      "note": "optional explanation"
    }
  ]
}
```

* `method` defaults to `extract`. For `extract`, the request is
  `{text: input, options, offsetUnit}`: `options.offsetUnit` is lifted to the
  request and defaults to `char`. Other methods (`annotate`, `clean`, ...) give
  the whole API request in `request` instead of `input`/`options`.
* `expect` is matched against the API response (or `{"error": {code,
  message}}` when the call fails).
* `status`: `pass` must match; `pending` must *not* match. A pending case that
  starts passing fails the run so its status gets flipped (`run.py --promote`),
  which keeps the pending list shrinking and turns every fix into a guarded
  regression test.
* `upstream` (ported cases) records what eyecite returned; it is not asserted.
* `divergence` (ported cases) explains a deliberate difference from eyecite;
  the regenerator keeps a hand-edited `expect` when it is present.

| File | Source |
|---|---|
| `eyecite-find.json` | eyecite `tests/test_FindTest.py` |
| `eyecite-models.json` | eyecite `tests/test_ModelsTest.py`, `test_UtilsTest.py` extraction inputs |
| `eyecite-resolve.json` | eyecite `tests/test_ResolveTest.py` (antecedents) |
| `eyecite-annotate.json` | eyecite `tests/test_AnnotateTest.py` (explicit spans, markup mapping) |
| `eyecite-clean.json` | eyecite `clean_text` calls |
| `commonwealth.json` | Authored Canadian/Commonwealth gold cases |

The `eyecite-*.json` files are generated by
[`tools/port-eyecite.py`](tools/port-eyecite.py) from real eyecite output at
the commit in [`tools/eyecite.lock.json`](tools/eyecite.lock.json); its
docstring lists the class-by-class mapping onto this model.

## Matching

`expect` is a partial description: only the listed keys are asserted.

* **object**: every listed key must match; unlisted keys are ignored.
* **array**: same length, element by element.
* **`null`**: the key is absent (or null).
* **scalar**: equal (numbers numerically, no bool/number coercion).
* **`{"$contains": [a, b]}`**: the actual array has elements matching `a`,
  then `b`, in order, possibly with others between (an ordered subsequence).
* **`{"$in": [x, y]}`**: the actual value matches one of the choices.

## Schema

[`schema/citation.schema.json`](schema/citation.schema.json) (JSON Schema
2020-12) describes the `extract` response. `schemaVersion` is 1; a breaking
change to the citation shape bumps it, a new optional property does not.
`crates/legal-citations-cli/tests/schema.rs` validates every conformance
input's output against it and fails on any property the schema lacks.
